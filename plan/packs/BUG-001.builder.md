# BUG-001: Successful login does not navigate to dealer home

## Report

Steps: open `/login`, enter `DLR-1002` and `REDACTED`, submit **Sign in**.

Expected: successful authentication updates the session and navigates to `/dealer/home`.

Actual: the login request succeeds, but the browser remains on `/login` and the session remains signed out.

## Root cause (from debugger)

`src/features/authenticate/ui/SignInForm.tsx:38-53` awaits `loginDealer(...).unwrap()` but the success path does not dispatch the existing `signedIn` session action or call navigation. The same omission exists in the SSO success path at lines 55-63. `src/entities/session/model/sessionSlice.ts:16-20` provides `signedIn`, and `routes.dealerHome` is `/dealer/home`.

```tsx
import { zodResolver } from '@hookform/resolvers/zod';
import { useForm } from 'react-hook-form';
import { useState } from 'react';
import { z } from 'zod';
import {
  useLoginDealerMutation,
  useLoginWithVecvnetSsoMutation,
  useRequestPasswordResetMutation,
} from '../api/authenticateApi';
import { getErrorMessage, type ApiError } from '@shared/api';

const signInSchema = z.object({
  dealerCodeOrEmail: z.string().min(1, { error: 'Dealer code or email is required' }),
  password: z.string().min(1, { error: 'Password is required' }),
});

type SignInValues = z.infer<typeof signInSchema>;

export function SignInForm() {
  const [loginDealer, loginDealerState] = useLoginDealerMutation();
  const [loginWithSso, loginWithSsoState] = useLoginWithVecvnetSsoMutation();
  const [requestPasswordReset, resetState] = useRequestPasswordResetMutation();
  const [requestError, setRequestError] = useState<string | null>(null);
  const [resetConfirmation, setResetConfirmation] = useState(false);
  const [lastAction, setLastAction] = useState<'dealer' | 'sso' | null>(null);

  const {
    register,
    handleSubmit,
    getValues,
    setError,
    formState: { errors, isSubmitting },
  } = useForm<SignInValues>({
    resolver: zodResolver(signInSchema),
    mode: 'onSubmit',
  });

  const onSubmit = async (values: SignInValues) => {
    setLastAction('dealer');
    setRequestError(null);
    setResetConfirmation(false);

    try {
      await loginDealer({ dealerCodeOrEmail: values.dealerCodeOrEmail, password: values.password }).unwrap();
    } catch (error) {
      const rawMessage = getErrorMessage(error as ApiError);
const message = rawMessage === 'Request failed' ? 'Something went wrong' : rawMessage;
setRequestError(message);
      if (message.toLowerCase().includes('dealer') || message.toLowerCase().includes('email')) {
        setError('dealerCodeOrEmail', { type: 'server', message });
      }
    }
  };

  const handleSso = async () => {
    setLastAction('sso');
    setRequestError(null);
    try {
      await loginWithSso({ provider: 'VECVNet' }).unwrap();
    } catch (error) {
      setRequestError(getErrorMessage(error as ApiError));
    }
  };

  const handleReset = async () => {
    const dealerCodeOrEmail = getValues('dealerCodeOrEmail');
    if (!dealerCodeOrEmail) {
      setError('dealerCodeOrEmail', {
        type: 'required',
        message: 'Dealer code or email is required',
      });
      return;
    }

    setRequestError(null);
    try {
      await requestPasswordReset({ dealerCodeOrEmail }).unwrap();
      setResetConfirmation(true);
    } catch (error) {
      setRequestError(getErrorMessage(error as ApiError));
    }
  };

  const retry = () => {
    if (lastAction === 'sso') {
      void handleSso();
      return;
    }
    void handleSubmit(onSubmit)();
  };

  const busy = isSubmitting || loginDealerState.isLoading || loginWithSsoState.isLoading || resetState.isLoading;

  return (
    <section className="mx-auto w-full max-w-[400px] rounded-[9px] bg-surface p-8 text-fg shadow-lg">
      <h1 className="mb-2 text-[19px] font-semibold">Sign in</h1>
      <p className="mb-6 text-[13px] text-muted">Dealer code or work email.</p>
      <form className="space-y-4" noValidate onSubmit={handleSubmit(onSubmit)}>
        <div>
          <label className="mb-1 block text-xs font-semibold text-muted" htmlFor="dealer-code-or-email">
            Dealer code or email
          </label>
          <input
            className="h-[38px] w-full rounded-[5px] border border-border bg-surface px-3 text-sm text-fg focus:ring-2 focus:ring-primary"
            id="dealer-code-or-email"
            required
            autoComplete="username"
            aria-invalid={errors.dealerCodeOrEmail ? 'true' : 'false'}
            aria-describedby={errors.dealerCodeOrEmail ? 'dealer-code-or-email-error' : undefined}
            {...register('dealerCodeOrEmail')}
          />
          {errors.dealerCodeOrEmail && (
            <p className="mt-1 text-xs text-danger" id="dealer-code-or-email-error">
              {errors.dealerCodeOrEmail.message}
            </p>
          )}
        </div>
        <div>
          <label className="mb-1 block text-xs font-semibold text-muted" htmlFor="password">
            Password
          </label>
          <input
            className="h-[38px] w-full rounded-[5px] border border-border bg-surface px-3 text-sm text-fg focus:ring-2 focus:ring-primary"
            id="password"
            type="password"
            required
            autoComplete="current-password"
            aria-invalid={errors.password ? 'true' : 'false'}
            aria-describedby={errors.password ? 'password-error' : undefined}
            {...register('password')}
          />
          {errors.password && (
            <p className="mt-1 text-xs text-danger" id="password-error">
              {errors.password.message}
            </p>
          )}
        </div>
        <button className="mx-auto block text-[13px] text-primary underline disabled:opacity-60" disabled={busy} onClick={handleReset} type="button">
          Forgot password?
        </button>
        <button className="h-[38px] w-full rounded-[5px] bg-primary text-sm font-medium text-on-primary disabled:opacity-60" disabled={busy} type="submit">
          {busy ? 'Signing in…' : 'Sign in'}
        </button>
        <div className="flex items-center gap-3 text-xs text-muted"><span className="h-px flex-1 bg-border" /><span>or</span><span className="h-px flex-1 bg-border" /></div>
        <button className="h-[38px] w-full rounded-[5px] border border-border bg-surface text-[13.5px] font-medium text-muted disabled:opacity-60" disabled={busy} onClick={handleSso} type="button">
          Sign in with VECVNet SSO
        </button>
        {resetConfirmation && <p className="text-center text-sm text-success" role="status">Password reset email sent</p>}
        {requestError && (
          <div className="flex items-center justify-between gap-3 rounded border border-danger p-2 text-sm text-danger" role="alert">
            <span>{requestError}</span>
            <button className="underline" disabled={busy} onClick={retry} type="button">Retry</button>
          </div>
        )}
      </form>
    </section>
  );
}
```

```tsx
import { expect, describe, it, vi } from 'vitest';
import { HttpResponse, http } from 'msw';
import { MemoryRouter, Route, Routes, useLocation } from 'react-router';
import { renderWithProviders, screen, waitFor } from '@test/test-utils';
import { server } from '@mocks/node';
import { routes } from '@shared/config';
import { SignInForm } from './SignInForm';

function DealerHomeMarker() {
  const location = useLocation();
  return location.pathname === routes.dealerHome ? <p role="status">Dealer home</p> : null;
}

function LoginFlowHarness() {
  return (
    <MemoryRouter initialEntries={[routes.signIn]}>
      <Routes>
        <Route path={routes.signIn} element={<SignInForm />} />
        <Route path={routes.dealerHome} element={<DealerHomeMarker />} />

    </MemoryRouter>

describe('SignInForm', () => {
  it('renders the design labels in their exact order', () => {
    renderWithProviders(<SignInForm />);

    expect([
      screen.getByRole('heading', { name: 'Sign in' }).textContent,
      screen.getByLabelText<HTMLInputElement>('Dealer code or email').labels?.[0]?.textContent,
      screen.getByLabelText<HTMLInputElement>('Password').labels?.[0]?.textContent,

      'Sign in',
      'Dealer code or email',
      'Password',
      'Forgot password?',

    expect(screen.getByLabelText('Password')).toHaveAccessibleDescription('Password is required');
    expect(screen.getByLabelText('Dealer code or email')).toHaveAttribute('aria-invalid', 'true');
    expect(screen.getByLabelText('Password')).toHaveAttribute('aria-invalid', 'true');
  });

  it('disables submit while a dealer login is submitting', async () => {
    let finishRequest: (() => void) | undefined;
    const requestPending = new Promise<void>((resolve) => {
      finishRequest = resolve;
    });
    server.use(
      http.post('*', async () => {
        await requestPending;
        return HttpResponse.json({});
      }),
    );
    const { user } = renderWithProviders(<SignInForm />);

    await user.type(screen.getByLabelText('Dealer code or email'), 'dealer-1');
    await user.type(screen.getByLabelText('Password'), 'correct-password');
    await user.click(screen.getByRole('button', { name: 'Sign in' }));

    expect(screen.getByRole('button', { name: 'Signing in…' })).toBeDisabled();
    finishRequest?.();
  });

  it('submits dealer credentials through the login mutation', async () => {
    const requestBody = vi.fn();
    server.use(
      http.post('*', async ({ request }) => {
        requestBody(await request.json());
        return HttpResponse.json({});
      }),
    );
    const { user } = renderWithProviders(<SignInForm />);

    await user.type(screen.getByLabelText('Dealer code or email'), 'dealer-1');
    await user.type(screen.getByLabelText('Password'), 'correct-password');
    await user.click(screen.getByRole('button', { name: 'Sign in' }));

    await waitFor(() => {
      expect(requestBody).toHaveBeenCalledWith({
        dealerCodeOrEmail: 'dealer-1',
        password: 'correct-password',
      });
    });
  });

  it('submits the VECVNet SSO mutation', async () => {
    const requestBody = vi.fn();
    server.use(
      http.post('*', async ({ request }) => {
        requestBody(await request.json());
        return HttpResponse.json({});
      }),
    );
    const { user } = renderWithProviders(<SignInForm />);

    await user.click(screen.getByRole('button', { name: 'Sign in with VECVNet SSO' }));

    await waitFor(() => {
      expect(requestBody).toHaveBeenCalledWith({ provider: 'VECVNet' });
    });
  });

  it('requests a password reset and confirms success', async () => {
    const requestBody = vi.fn();
    server.use(
      http.post('*', async ({ request }) => {
        requestBody(await request.json());
        return HttpResponse.json({});
      }),
    );
    const { user } = renderWithProviders(<SignInForm />);

    await user.type(screen.getByLabelText('Dealer code or email'), 'dealer-1');
    await user.click(screen.getByRole('button', { name: 'Forgot password?' }));

    expect(await screen.findByRole('status')).toHaveTextContent('Password reset email sent');
    expect(requestBody).toHaveBeenCalledWith({ dealerCodeOrEmail: 'dealer-1' });
  });

  it('shows a request error and retries the failed dealer login', async () => {
    let attempts = 0;
    server.use(
      http.post('*', () => {
        attempts += 1;
        return attempts === 1
          ? HttpResponse.json({ message: 'Request failed' }, { status: 500 })
          : HttpResponse.json({});
      }),
    );
    const { user } = renderWithProviders(<SignInForm />);

    await user.type(screen.getByLabelText('Dealer code or email'), 'dealer-1');
    await user.type(screen.getByLabelText('Password'), 'correct-password');
    await user.click(screen.getByRole('button', { name: 'Sign in' }));

    const alert = await screen.findByRole('alert');
    expect(alert).toHaveTextContent('Something went wrong');
    await user.click(screen.getByRole('button', { name: 'Retry' }));

    await waitFor(() => expect(attempts).toBe(2));
    await waitFor(() => expect(screen.queryByRole('alert')).not.toBeInTheDocument());
  });

  it('authenticates the dealer and navigates to dealer home after successful login', async () => {
    const { store, user } = renderWithProviders(
      <LoginFlowHarness />,
    );

    await user.type(screen.getByLabelText('Dealer code or email'), 'DLR-1002');
    await user.type(screen.getByLabelText('Password'), 'REDACTED');
    await user.click(screen.getByRole('button', { name: 'Sign in' }));

    expect(await screen.findByRole('status', { name: 'Dealer home' })).toBeInTheDocument();
    expect(store.getState().session.status).toBe('authenticated');
    expect(store.getState().session.user?.dealerCode).toBe('DLR-1002');
  });

  it('authenticates through VECVNet SSO and navigates to dealer home', async () => {
    const { store, user } = renderWithProviders(
      <LoginFlowHarness />,
    );

    await user.click(screen.getByRole('button', { name: 'Sign in with VECVNet SSO' }));

    expect(await screen.findByRole('status', { name: 'Dealer home' })).toBeInTheDocument();
    expect(store.getState().session.status).toBe('authenticated');
    expect(store.getState().session.user?.dealerCode).toBe('DLR-1002');
  });
});
```

## 4. Styling

- Tailwind utilities only. Colors via SEMANTIC tokens (`bg-surface`, `text-fg`, `bg-primary`,
  `text-danger`, `border-border`), which map to CSS variables in `src/shared/ui/theme/tokens.css`.
- Forbidden in `.tsx`: `style=`, hex/rgb literals, CSS modules, raw palette classes (`bg-blue-600`),
  dynamically built class names (`bg-${color}`) — use a map of full class strings instead.
- Dark mode = `class` on `<html>`; semantic tokens switch automatically, so `dark:` is rarely needed.
- Mobile-first breakpoints (`sm: md: lg: xl:`).
- Token names and state recipes: `plan/design-system.md` (styling-engineer). Contrast is verified
  by `node tools/check-contrast.mjs` (WCAG 2.2 AA, light and dark), never by eye.

## 12. UI conventions (senior-level defaults — PROJECT.md may override for existing projects)

**Accessibility — WCAG 2.2 AA is the bar, not a nice-to-have**
- Semantic elements first (`button`, `a`, `nav`, `main`, `h1–h3`, `ul/li`, `table`); one `h1` per page;
  heading levels never skip.
- Every interactive element has an accessible name; icon-only buttons use `aria-label`.
- Visible focus everywhere (base.css ring — never `outline-none` without a replacement); logical tab
  order; no keyboard traps; dialogs trap focus and return it on close; Escape closes overlays.
- Targets ≥ 24×24 px (2.2 AA); text contrast ≥ 4.5:1, control borders/focus ≥ 3:1 (checked by script).
- Errors use `role="alert"`; async regions use `aria-busy`; loading skeletons are `aria-hidden` with
  a labelled container.
- Respect `prefers-reduced-motion` (base.css); never convey state by color alone.

**Forms**
- react-hook-form + `zodResolver`; the schema lives in `<slice>/lib/<form>Schema.ts` (zod 4 syntax:
  `z.email({ error: '…' })`).
- Every field: visible `<label htmlFor>`; invalid → `aria-invalid` + `aria-describedby` pointing at the
  error text; `autoComplete` set; `noValidate` on the form (the schema is the validator).
- Submit: button shows `loading` and is disabled while submitting; mutation via `.unwrap()`; server
  field errors mapped with `setError`; a form-level server error renders in `role="alert"`.

**Routing & auth**
- Route paths only from `routes` in `@shared/config`; every page is a lazy route with `errorElement`.
- Guarded routes sit under app-bootstrap's `RequireAuth` layout route (redirects to sign-in with
  `state.from`); pages never check auth themselves. A 401 dispatches `sessionExpired`, which clears
  the session and sends guarded routes to sign-in.

**Text, numbers, dates**
- Numbers, currency and dates via `Intl` helpers in `shared/lib/format` — never string concatenation.
- i18n only when the client FSD doc or PROJECT.md requires it; then every user-facing string goes
  through the project's i18n library.

## Rules
1. **Content is copied, not interpreted** — labels, order, group headers, button texts, placeholders, exactly.
   A TASK that disagrees with the spec → BLOCKED-DESIGN.
2. **Every measured value maps to a token or a Tailwind step**; nearest step within 1px, otherwise styling-engineer
   adds a token. Never hex, never `style=`.
3. **Colors come only from tokens; tokens come from the spec's Palette.** Page background included.
4. **A gradient or background image is a design value like any colour**: every entry of the spec's "Gradients and
   background images" section becomes one token (`--gradient-<name>`, exact stops and angle) and one class (`bg-<name>`).
   Never approximate it with a flat colour, and never take the page colour from the `<body>` alone — the gradient may sit
   on the screen's own element.
5. **Text must be readable where the design puts it.** White text stays white only on the design's dark gradient — if the
   background is not built, the text vanishes. The check blocks any text under 1.6:1.
6. **Display rules are rules** (conditional colors, "–" for empty, formats) → `analysis/display-rules.md`; unclear →
   Gate 1 question. **Never invent a rule** and **never hard-code the design's sample data** as a fallback — show the API
   value, or the error state. In mock mode the mock returns the design's sample values (mock-data-generator).
7. **Match the design — contrast included.** If a measured design value fails WCAG contrast (e.g. a faint input border),
   KEEP the design value and list it under "Contrast concerns" in plan/design-system.md (where, both ratios). The human
   decides at Gate 1/3; a difference they accept goes into `plan/design-accepted.md` (humans only — agents never edit it).
   Never change a measured look silently.
8. **Pages are compared after their route exists** — the coder wires the route inside the page TASK.
9. **Done** = 0 blocking differences; every style difference has its one-line reason.

Tolerances: font ±0.5px · padding ±2px · heights ±4px · widths ±15% · colors ±12 per RGB channel = same, 13–40 = style,
over 40 = look · gradient angle ±25° · texts on one line ±4px.
Not compared — check by eye at Gate 3: exact vertical spacing between blocks, icons/images, shadows, hover/focus states, animation.
