# BUG-001: Successful login does not navigate

## Report

Login success does not navigate to `/dealer/home`; `SignInForm` awaits the mutation but does not update session or redirect.

## Reproduction

1. Start the app in mock mode and open `/login`.
2. Enter dealer code `DLR-1002` and password `REDACTED`.
3. Submit **Sign in**.
4. Observe that the login request succeeds but the browser remains on `/login`.

Existing isolation command:

`node tools/run.mjs npx vitest run src/features/authenticate/ui/SignInForm.test.tsx --reporter=dot`

Result: 1 test file and 8 tests passed. The existing tests do not assert post-success session state or navigation, so the bug is currently untested rather than reproduced as a failing assertion.

## Root cause

`src/features/authenticate/ui/SignInForm.tsx:38-53` awaits `loginDealer(...).unwrap()` and exits on success. There is no dispatch of the existing `signedIn` action and no `useNavigate()` call. `src/entities/session/model/sessionSlice.ts:16-20` already provides the required authenticated-state transition, while `src/app/router.tsx:28-33` defines the dealer destination at `/dealer/home`.

Evidence: the success path ends immediately after line 44; only the `catch` branch handles UI state. The login mutation invalidates the `Session` tag but no query is subscribed to that tag, so invalidation cannot establish client session state or cause routing.

## Files that need changing

- `src/features/authenticate/ui/SignInForm.tsx` — on successful dealer and SSO authentication, dispatch the returned user through `signedIn` and navigate to `routes.dealerHome`.
- `src/features/authenticate/ui/SignInForm.test.tsx` — add regression coverage for successful dealer login, session authentication, and navigation; update SSO success coverage if the same contract applies.

## Regression test idea

Regression type: unit

Render `SignInForm` with a fresh `renderWithProviders` store and a memory router containing `/login` and `/dealer/home` (the destination renders a uniquely named marker). Submit `DLR-1002` / `REDACTED`, await the destination marker, and assert the store's session selector reports authenticated with the returned user. This fails today because the form remains on `/login` and the session remains signed out.

## Risks and neighbours

- SSO uses the same missing success handling at `SignInForm.tsx:55-63`; it should follow the same session/navigation contract.
- The mock login response contains a user but no token; the session action supports an optional token, so this is not a blocker for mock mode.
- Do not add a separate auth mechanism or fetch; keep RTK Query as the server-data mechanism and use the existing session slice.
