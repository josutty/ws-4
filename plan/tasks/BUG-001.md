# BUG-001: Successful login does not navigate to dealer home

## Report

Steps: open `/login`, enter `DLR-1002` and `REDACTED`, submit **Sign in**.

Expected: successful authentication updates the session and navigates to `/dealer/home`.

Actual: the login request succeeds, but the browser remains on `/login` and the session remains signed out.

## Root cause (from debugger)

`src/features/authenticate/ui/SignInForm.tsx:38-53` awaits `loginDealer(...).unwrap()` but the success path does not dispatch the existing `signedIn` session action or call navigation. The same omission exists in the SSO success path at lines 55-63. `src/entities/session/model/sessionSlice.ts:16-20` provides `signedIn`, and `routes.dealerHome` is `/dealer/home`.

Type: unit — `successful dealer login authenticates the session and navigates to dealer home`.

Render the form with a fresh store and a memory router containing `/login` and `/dealer/home`; submit `DLR-1002` / `REDACTED`; assert the dealer-home marker is rendered and the session selector reports authenticated with the returned user. This must fail on the current code because the form remains on `/login` and no `signedIn` action is dispatched. Also cover successful VECVNet SSO with the same session/navigation contract.

## Must not change

- Keep the existing RTK Query login and SSO mutations and `.unwrap()` error handling.
- Keep the existing invalid, loading, retry, password-reset, and exact-label behaviour.
- Do not add a second authentication/data-fetch mechanism or alter API contracts.
- Use `routes.dealerHome`; do not hard-code a route string.
- Do not alter the session slice, router definitions, mock handlers, or page content.
